# Changelog

All notable changes to the Covenant Media Unified Digital Platform are documented in this file.

The format is loosely based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Dates are UTC. The repository's Git history is the authoritative record; this changelog summarizes meaningful milestones.

> Note: the repository contains a single squashed/initial commit at the time this changelog was initialized, so earlier history (pre-`738c87a`) is not reconstructible from git alone. Pre-history entries below summarize features that clearly exist in the codebase at initialization rather than fabricating individual commits.

### Added
- **2026-09-12 — CMS console redesign (owner's brief: clear it out and rebuild it clean).** Scope was the CMS only; the Media Portfolio, Tech Portfolio and main landing page were not touched.
  - **Overview.** `/admin` reports the three public surfaces in one place — video links, hero reel, photographs, client stories, social profiles, enquiries, services, team — with a *Needs your attention* panel that names what the public pages cannot fill in on their own (unverified socials, placeholder projects, missing canonical URL).

    - **Hero preview toggle** on short-form links: on → the piece opens the hero; off → it stays in the short-form rail under *View Catalog*. Long-form links have no toggle and the server refuses a `hero-on` for them.

    - **Client stories** attach to a video from a dropdown and carry the client name, video type and quote.   - **All content** (`/admin/content`) is the index of every registry module, so nothing the CMS can edit is more than two clicks from anywhere.
  - Tech portfolio gets sidebar placement only, deliberately, until it is built out.

### Fixed
- **Photographs larger than 1MB could not be uploaded at all.** Next caps server-action request bodies at 1MB by default; a real event photograph was rejected by the framework with a 500 before the upload action's own *too large* message could explain it. `next.config.mjs` now derives `serverActions.bodySizeLimit` from `STORAGE_MAX_UPLOAD_MB` (32MB by default, plus headroom), and `middlewareClientMaxBodySize` matches it so the middleware in front of `/admin/*` does not truncate the body first.
- **The CMS error page blamed the database for everything.** It now reports the message it actually has and only reaches for the "could not reach its database" explanation when the failure looks like one — an oversized upload no longer sends the owner chasing a healthy database.
- **Two audit rows were written per console action.** `repository.ts` audits every write, and the console actions audited again on top. The repository now takes an optional summary, so there is one row per action with the readable wording ("Added a service — Videography", "Verified a social profile").
- **The admin form controls were not a client component.** `SubmitButton`/`ActionButton` use `useFormStatus`, so any console screen rendering them crashed at build time.
- `schema.sql` and `tables.ts` drifted apart on `media_video.hero_preview`: the column was added by `ALTER TABLE`, which the drift test could not see, so it failed against a schema that was in fact correct. The test now reads additive `ALTER TABLE … ADD COLUMN` as well as `CREATE TABLE`.

### Security
- **The CMS sign-in page no longer prints any credentials (2026-09-12).** It used to render a "Development seed" hint showing the seeded email and password whenever `NODE_ENV !== 'production'` and `ADMIN_SEED_VISIBLE !== '0'` — so any reachable `/admin/login` on a non-production deploy handed over working owner credentials. The hint and its `devHint` / `ADMIN_SEED_VISIBLE` plumbing are gone; the page now renders the form and nothing else, in every environment.
- **Owner accounts.** The CMS is now owned by the studio's own accounts (`covenantmedia0015@gmail.com` and `covenantmedia015@gmail.com`, both role `owner`) and the seeded demo account `covenant@example.test` was deleted, so no known default credential is left behind. Passwords live only in the local database — `.cm-data/` and `.env` are gitignored, so nothing secret is committed.

### Added
- **2026-09-10 — Media Portfolio video/embed layer and sample content model.** *Partly superseded by the 2026-09-11 entry below: the hero is now a continuously rolling non-clickable reel, the filterable grid and the full-bleed theatre were replaced by the card and the details card, and the sample content is now the owner's own published work rather than twelve simulated rows. `lib/media/embed.ts` and `MediaVideoPlayer` remain, both still in use.* New media-only modules, all additive:
  - `src/lib/media/embed.ts` — platform capability matrix + `resolvePlayable` / `buildEmbed` / `platformLabel`. Wraps the existing `detectVideoSource` from `lib/media/video.ts` (unmodified) and adds what the old helper lacked: a per-platform declaration of what is *actually* possible. `CAPABILITIES` records `mutedAutoplay`, `controllableMute`, `posterDerivable`, `embeddable` and `aspect` for YouTube, Vimeo, TikTok, Facebook, Instagram, direct `upload` files and plain `external` links, so the UI can adapt instead of assuming. `buildEmbed` appends the real mute parameters (`mute=1` / `playlist=` for YouTube, `muted=` / `background=` for Vimeo) and, for platforms that expose no keyless mute or no keyless poster (TikTok, Facebook, Instagram), returns the plain embed — the honest fallback: poster + platform credit, embed only after a click. YouTube posters derive from `i.ytimg.com`, already in `next.config.mjs` `remotePatterns`.
  - `src/lib/media/sample-portfolio.ts` — `MediaItem` + 12 simulated items, 8 services and a 5-step process, shaped to mirror the `project` / `media_video` / `media_asset` columns so a real loader can replace the arrays without touching the components. Categories are drawn from the existing `MEDIA_CATEGORIES` option list; every row is `isSample: true` so the shared Placeholder badge renders; no database writes, and the four seeded YouTube URLs are reused rather than inventing working media.
  - `src/components/site/MediaVideoPlayer.tsx` — `MediaVideoPlayer` (in-page, IntersectionObserver-gated, muted autostart only while visible, returns to idle off-screen so a long page never runs several players; reduced-motion disables autostart entirely) and `MediaTheatre` (full-bleed viewer, opens muted where the platform supports it, Esc to close, body scroll locked). Direct file URLs (`lib/media/video.ts` `upload` source) render a native `<video>` instead of an iframe — that is the only way muted autoplay works for a self-hosted file. Rendered inside the media page rather than the shared `LightboxHost`, so the main and tech surfaces keep the lightbox behaviour they had.
  - `src/components/site/MediaRoleLine.tsx` — vertical upward role ticker for the hero (hold 2600 ms / travel 720 ms, `prefers-reduced-motion` falls back to the joined list). Distinct from the tech `RoleSweep`'s horizontal clip-path wipe: same craft, different signature.

A host with no supported embed (`lib/media/video.ts` `external` source) presents as an outbound link card with an external-link glyph rather than a play button that could never play.

#### CMS (`/admin`)
- Full CMS back office with grouped navigation, search ("Jump to…"), role badges, responsive drawer, account page, sign-out, and "View site" link.
- Session-cookie authentication (httpOnly `cm_session` + double-submit CSRF cookie), scrypt password hashing, per-IP login throttling via `auth_attempt` table, account lockout after repeated failures, password change, "sign out other sessions".
- Role-based access control with four system roles (`owner`, `editor`, `media_editor`, `viewer`) supporting per-module permissions and DB-overridable role maps cached for 30 seconds. Every mutation enforces permissions server-side; UI hides disallowed actions.
- Audit logging (`audit_log` table) on every mutation (create/update/delete/publish/upload/login) with user, module, entity, summary, IP, timestamp.
- Generic module registry (`src/lib/cms/modules.ts`) driving all 24 admin modules without per-module screens: list, search, filters (category/division/form), sort, pagination, create, edit, publish/draft/archive, duplicate (where enabled), delete with reference check, reorder (drag-and-drop), "feature" toggles, "verify social link", "activate resume" (enforces exactly one active version).

- Specialized editors: media library grid, video editor (paste-a-link source detection, oEmbed fetch, metadata override, poster preview), navigation tree editor, page block composer (attach/detach/reorder/toggle sections with per-block overrides), settings editor grouped by category with custom settings, SEO record editor, resume manager, submissions inbox with triage statuses (new/read/replied/archived/spam), featured content picker.
- Asset upload endpoint with MIME sniffing, size limits (configurable via `STORAGE_MAX_UPLOAD_MB`), Sharp image variants (thumbnails), checksum, blur placeholders, folder tagging, alt/caption/credit metadata; replace-asset flow that preserves the asset ID everywhere it is referenced.
- CSV export for contact submissions (`/api/admin/export/submissions`).
